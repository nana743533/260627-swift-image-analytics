## 3. Git運用ルール

### 3.1 ブランチ運用
基本的に `main` ブランチから作業用ブランチを切り、作業完了後に Pull Request (PR) を経由して `main` へマージします。

```text
main
  └─ feat/headphone-motion              ← 機能開発
  └─ docs/sync-current-implementation   ← ドキュメント整備
  └─ feat/how-chat                      ← 機能開発
  └─ fix/airpods-disconnect             ← バグ修正
  └─ docs/update-spec                   ← 仕様更新
```

### 3.2 コミットメッセージのプレフィックス
履歴をわかりやすくするため、コミットメッセージの先頭に以下のプレフィックスを付与します。

- `feat:` 新機能の実装
- `fix:` バグ修正
- `docs:` ドキュメントの追加・修正
- `style:` コードの意味に影響を与えない変更（インデント調整、余白追加など）
- `refactor:` リファクタリング（機能追加やバグ修正を含まないコードの整理）
- `chore:` ビルドツールや設定ファイルの変更、ライブラリ追加など

**コミットメッセージの例**:
```text
feat: カメラ起動用の SwiftUI ビューを追加
docs: プロジェクトのビルド高速化ガイドラインを追加
```
